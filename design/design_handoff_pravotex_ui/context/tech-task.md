# Задание: UI/UX агентной платформы для юристов

## Контекст

Мы строим B2B-платформу, в которой AI-агент выполняет работу юриста: ведет дело, работает с документами и сроками, предлагает действия — юрист подтверждает, изменяет или отклоняет. Один и тот же агент присутствует во всех частях продукта.

Интерфейс сейчас видится двухуровневым, с одной грамматикой на обоих уровнях — диалог в центре, карточки действий справа:

```
Уровень 1 — «Сегодня» (вход в платформу)

┌────┬──────────────────────────────┬────────────────────┐
│    │                              │  Очередь карточек  │
│ Р  │  Дневной чат с агентом:      │  действий P0–P3    │
│ е  │  утренний дайджест,          │  со всех рабочих   │
│ й  │  «что требует внимания»,     │  пространств       │
│ к  │  вопросы в свободной форме   ├────────────────────┤
│ а  │                              │  Календарь         │
│    │                              │  ближайших сроков  │
└────┴──────────────────────────────┴────────────────────┘

Уровень 2 — рабочее пространство (например, обязательства в портфеле договоров юриста или судебных дел)

┌────┬─────────────────┬──────────────────┬────────────────────┐
│    │  Чаты с агентом │                  │  Карточки действий:│
│ Р  │  (список        │  Текущий чат:    │  подтвердить /     │
│ е  │  разговоров-    │  диалог,         │  изменить /        │
│ й  │  задач)         │  стриминг,       │  отклонить         │
│ к  ├─────────────────┤  ссылки на       ├────────────────────┤
│ а  │  Вкладки:       │  источники       │  Календарь         │
│    │  Дела ·    │                  │  пространства      │
│    │  События        │                  │                    │
└────┴─────────────────┴──────────────────┴────────────────────┘

Рейка — узкая навигация слева: «Сегодня», рабочие пространства, настройки.
```

Рамки, важные для дизайна:

- Рабочее пространство = продукт внутри платформы: свой набор навыков агента, свои типы контекста (документы, события) и типы карточек. Новые продукты добавляют типы, но не меняют раскладку.
- Чат — это разговор-задача. Документами и очередью карточек владеет пространство, чат — только разговором.
- Карточка действия — главный механизм контроля: агент предлагает, юрист решает. Одна и та же карточка живёт и в очереди «Сегодня», и в своём пространстве. Приоритет P0–P3 считает платформа, интерфейс его только отображает.
- Каждый вывод агента ссылается на источник, источник кликабелен: открывает документ в нужном месте.
- Латентность агента — реальность: долгие операции показываются честно (статусы, прогресс), а не бесконечным спиннером.

## Задание

Спроектируйте и соберите работающий прототип этого интерфейса: оба уровня, переход между ними, диалог с агентом, карточки действий, документы, календарь.

- Схема выше — то, как мы видим интерфейс сейчас. Ваш собственный подход приветствуется: можно спорить с раскладкой и предлагать своё решение — с аргументами.
- Помните: строится платформа, а не один экран. Нужны типовые поверхности и переиспользуемые модули, из которых будут собираться новые рабочие пространства.
- Агента можно замокать (заготовленные ответы), но интерфейс должен ощущаться живым: стриминг ответа, статусы операций, состояния загрузки, продуманные пустые состояния.
- Наполните прототип демо-данными (документы, события, карточки, сроки), чтобы по интерфейсу можно было пройти сценарий юриста, а не смотреть на пустые панели.
- Стек — на ваше усмотрение (мы живём в React + TypeScript, но для прототипа это опционально).
