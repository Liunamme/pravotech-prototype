# ПравоТех

**AI-агент выполняет работу юриста. Юрист остаётся тем, кто решает.**

[![CI](https://github.com/Liunamme/pravotech-prototype/actions/workflows/ci.yml/badge.svg)](https://github.com/Liunamme/pravotech-prototype/actions/workflows/ci.yml)
[![Deploy](https://github.com/Liunamme/pravotech-prototype/actions/workflows/deploy.yml/badge.svg)](https://github.com/Liunamme/pravotech-prototype/actions/workflows/deploy.yml)

### → [Открыть прототип](https://liunamme.github.io/pravotech-prototype/)

Рабочий прототип B2B-платформы: агент ведёт дела и договоры, следит за сроками и
предлагает готовые действия — юрист подтверждает, изменяет или отклоняет каждое.
Один и тот же агент присутствует во всех частях продукта, а не живёт отдельным
чат-окном сбоку.

Сделано по тестовому заданию (`tech-task.md`).

---

## Что показывает прототип

**Агент предлагает — юрист решает.** Каждое предложение приходит карточкой с
тремя исходами: подтвердить, изменить, отклонить. Правка идёт формой на месте с
подсветкой изменённых полей. Обратимые действия закрываются тостом с «Отменить»,
необратимые — подача в суд — требуют подтверждения в диалоге: механизм различает
одно от другого.

**Каждое утверждение обосновано.** Ссылка на «п. 7.3» открывает договор ровно на
этом пункте, рядом с чатом, и попадает в адрес страницы — такой ссылкой можно
поделиться. Целостность ссылок проверяется при загрузке: битая падает громко, а
не молча.

**Честная латентность.** Три класса ожидания: до 300 мс — без индикатора,
0.3–3 с — статус прямо в потоке чата с прогрессом, дольше — операция уезжает в
фоновый лоток и юрист свободен. Бесконечного спиннера без подписи в интерфейсе
нет.

**Платформа, а не экран.** Ядро не знает о конкретных рабочих пространствах.
Новое пространство — это один манифест и сид-данные, без единой правки в ядре и
без изменения раскладки. В прототипе два разнотипных пространства с разными
типами карточек, вкладками контекста и навыками агента — это и есть
доказательство переиспользуемости.

## Как посмотреть за пять минут

1. **`/#/today`** — агент стримит утренний дайджест со ссылками на источники.
   Справа очередь карточек со всех пространств и ближайшие сроки.
2. Нажмите **«п. 7.3»** в сообщении — договор откроется справа на нужном пункте,
   чат останется виден.
3. Разберите карточку: **Подтвердить / Изменить / Отклонить**. «Изменить»
   раскрывает форму с подсветкой правок; после решения — тост с «Отменить».
4. Спросите **«какие договоры продлятся автоматически»** — увидите честный
   прогресс «Читаю договоры · 7 из 12».
5. Спросите **«подготовь позицию по делу А40»** — тяжёлая операция уйдёт в фон,
   интерфейс не заперт, по завершении придёт уведомление.
6. Перейдите в пространство в левой рейке — **та же грамматика на втором
   уровне**: чаты-задачи, вкладки контекста, своя очередь.

Проверьте на прочность: кнопка **«Остановить»** во время стриминга, запрос про
**«выписку из ЕГРЮЛ»** (честная ошибка внешнего сервиса с «Повторить»), слово
**«расторжение»** (агент задаёт уточняющий вопрос), переключатель темы — и
сужение окна до планшета и телефона.

## Адаптив

Одна кодовая база, три раскладки. Пороги — в `src/shared/lib/breakpoints.ts`.

| Ширина окна | Раскладка |
|---|---|
| **≥ 1280** | три колонки: навигация, диалог, очередь и сроки |
| **768–1279** | рейка и сайдбар остаются, очередь уезжает в выдвижную панель |
| **< 768** | нижние вкладки, по одной поверхности за раз, настройки листом снизу |

Плюс правило: окно ниже 500px считается мобильным при любой ширине — это телефон
в альбомной ориентации и открытая экранная клавиатура.

## Запуск

Нужен **Node 22** (зафиксирован в `engines`, та же версия в CI).

```bash
npm install
npm run dev
```

Прод-сборка и локальный предпросмотр:

```bash
npm run build
npm run preview
```

Проверки — те же, что гоняет CI:

```bash
npm run lint         # oxlint, предупреждений быть не должно
npm test             # vitest, 77 тестов
npm run dry-run      # прогон всех сценариев агента в консоль, без UI
npm run check:dist   # собранный CSS не потерял стандартные свойства
npm audit --omit=dev --audit-level=high
```

## Архитектура

```
src/
  app/          роутер, провайдеры, тема
  shared/       ui/ (примитивы) · lib/ (утилиты, даты, пороги) · styles/ (токены)
  core/         layout · chat · cards · calendar · documents · tasks · agent
  workspaces/   registry + obligations/ + litigation/ — манифесты пространств
  store/        Zustand-слайсы, селекторы, dev-проверки целостности сидов
  pages/        TodayPage · WorkspacePage · SettingsPage
  types/        доменная модель
docs/           SPEC · DOMAIN · SCENARIOS · UX · APP-STRUCTURE — контракты проекта
docker/         конфигурация nginx для образа
```

**Транспорт агента подменяем.** UI работает с интерфейсом `AgentTransport`,
отдающим поток событий (`token` / `status` / `citation` / `card` / `handoff` /
`error`). Мок реализует этот интерфейс; замена на реальный SSE — одна строка в
провайдере, компоненты не меняются.

**Одна карточка — один рендерер.** Карточка в очереди «Сегодня» и в своём
пространстве — одна запись стора, отрисованная одним компонентом. Решение,
принятое в одном месте, немедленно видно в другом.

**Решение принимается один раз.** У карточки есть машина состояний: решение —
только из «не решено», исполнение — только из принятого решения, повтор — только
из сбоя. Двойной клик, вторая вкладка и запоздавший ответ не создают второго
действия.

**Сроки не пересчитываются в часовой пояс читателя.** Срок — юридический факт в
своём смещении, поэтому правка даты меняет только календарный день. Проверено
тестами под четырьмя часовыми поясами, включая переход на летнее время.

**Сроки и очередь — вкладками, а не двумя блоками подряд.** Исходная схема
предполагала календарь под очередью; здесь это переключатель. Причина: оба
списка длинные и конкурируют за одну вертикаль, а блок «Ближайшее» остаётся
виден всегда. Решение осознанное — не «вернуть как было».

Подробные контракты — в `docs/`. Там же, в `docs/SPEC.md`, раздел «Ловушки
платформы»: пятнадцать граблей, на которые уже наступали, с объяснением каждой.

## Стек

Vite · React 19 · TypeScript (strict) · React Router 8 (HashRouter) · Zustand ·
CSS Modules · Radix UI · lucide-react · date-fns · Vitest.

Дизайн-система собственная, на семантических токенах
(`src/shared/styles/tokens.css`), светлая и тёмная темы. UI-примитивы построены
на headless-примитивах Radix — готовая доступность со своей стилизацией, без
UI-китов, чтобы сохранить полный контроль над плотностью и поведением.

Сборка разведена по чанкам: react 220 кБ, radix 106 кБ, иконки 21 кБ, даты 32 кБ,
прикладной код 246 кБ — между релизами библиотеки остаются в кэше браузера.

## Тесты

`npm test` — 77 тестов, среда node. Покрыта логика, где ошибка тихая и дорогая:
правка сроков в разных часовых поясах, проверка форм карточек, машина состояний
решения, порядок очереди, разбор сбоев транспорта, темы диалогов, генерация
идентификаторов, пороги адаптива на реальных размерах устройств.

Рендер компонентов и сквозные сценарии тестами не покрыты сознательно: интерфейс
проверяется вручную и скриптами Playwright — замерами геометрии и скриншотами в
обеих темах на всех трёх раскладках.

## CI/CD

`.github/workflows/ci.yml` — линт (предупреждения считаются ошибками), типы,
тесты, сухой прогон агента, сборка, проверка собранного CSS, аудит
production-зависимостей. Гоняется на каждый pull request.

`.github/workflows/deploy.yml` вызывает те же проверки и публикует на GitHub
Pages только после
зелёного результата. Ветка `main` защищена: прямой push отклоняется, изменения
идут через pull request с обязательными проверками. Обновления зависимостей ведёт
Dependabot.

### Контейнер

Для GitHub Pages не нужен — образ на случай своего хостинга:

```bash
docker build -t pravotech .
docker run --rm -p 8080:8080 pravotech
```

Две стадии, раздача через `nginx-unprivileged` (работает не от root), заголовки
безопасности в `docker/nginx.conf` — CSP, `X-Content-Type-Options`,
`Referrer-Policy` и прочее, чего GitHub Pages настроить не даёт.

## Границы прототипа

Это прототип, и он честно ограничен:

- **агент замокан** — сценарии в `src/core/agent`, ни одного обращения к LLM или
  внешним сервисам; сеть из браузера не используется вовсе;
- **нет входа и разграничения доступа** — открывший ссылку видит всё;
- **ничего не сохраняется** — состояние живёт в памяти вкладки, перезагрузка
  начинает демонстрацию с чистого листа. Это выбор, а не недоделка: показ должен
  быть предсказуемым;
- **проверка форм — только ради интерфейса.** Она не даёт отправить пустое
  уведомление или платёж на ноль и объясняет, что не так, но защитой не является.

## Что нужно добавить к продукту

Прототип доходит до границы, за которой начинается доверенная сторона. Вместе с
реальным API должны появиться:

- **SSO/OIDC, роли и изоляция арендатора** на каждой операции;
- **проверка на сервере** — те же правила, что в формах, плюс выборка карточки по
  id и сверка роли, состояния и допустимости перехода: клиенту нельзя верить ни в
  payload, ни в идентификаторах;
- **идемпотентность необратимых действий** — ключ идемпотентности и ожидаемая
  версия карточки; клиентская защита от повторов есть, но она только клиентская;
- **журнал необратимых действий**: кто, когда, что подтвердил и какую версию текста;
- **лимиты размера, rate limiting, CSRF** там, где появятся cookie;
- **заголовки безопасности** — GitHub Pages их не даёт, для настоящего кабинета
  нужен другой хостинг; заготовка лежит в `docker/nginx.conf`;
- **защита от prompt injection на стороне оркестрации**: документы и сообщения —
  данные, а не инструкции; список разрешённых инструментов, подтверждение юристом
  и проверка политики на сервере обязательны.

## Про линт

`design/**` (выгрузка макета) и `dist/**` из проверки исключены — это не наш код.

Правило `react/only-export-components` точечно отключено для
`src/workspaces/**/cards/*.tsx`, `ThemeProvider` и `Toast`: там компонент лежит рядом
со своим контрактом (`CardTypeDef` объединяет `Body`, `EditForm`, `validate` и
`execute`) или провайдер рядом со своим хуком. Разносить их по файлам — ломать
контракт ради подсказки о fast refresh. Других отключений нет, и в CI любое новое
предупреждение роняет сборку.
