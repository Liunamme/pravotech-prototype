# ПравоТех — прототип агентной платформы для юристов

Рабочий прототип B2B-платформы, в которой AI-агент выполняет работу юриста: ведёт дело,
работает с документами и сроками, предлагает действия — а юрист подтверждает, изменяет
или отклоняет. Один и тот же агент присутствует во всех частях продукта.

Прототип отвечает на тестовое задание (`tech-task.md`). Агент замокан заготовленными
сценариями, но интерфейс живой: стриминг ответа по токенам, честные статусы длинных
операций с прогрессом, уход тяжёлых задач в фон, кликабельные источники у каждого
утверждения агента.

## Запуск

Нужен Node 18+ (проект собран на Node 22).

```bash
npm install
npm run dev      # http://localhost:5173
```

Прод-сборка и локальный предпросмотр:

```bash
npm run build    # tsc -b && vite build → dist/
npm run preview
```

Прочие команды:

```bash
npm run dry-run  # прогон всех сценариев мок-агента в консоль (без UI)
npm run lint     # oxlint
```

## С чего начать осмотр

1. **`/#/today` — уровень 1 «Сегодня».** При входе агент стримит утренний дайджест со
   ссылками на источники; справа — очередь карточек действий со всех пространств и сроки.
2. Кликните по источнику в сообщении (напр. «п. 7.3») — **документ открывается справа
   в нужном месте**, чат остаётся виден.
3. Разберите карточку в очереди: **Подтвердить / Изменить / Отклонить**. «Изменить»
   раскрывает форму на месте с подсветкой правок; после решения — тост с «Отменить».
4. Спросите **«какие договоры продлятся автоматически»** — увидите честный прогресс
   «Читаю договоры · 7 из 12».
5. Спросите **«подготовь позицию по делу А40»** — тяжёлая операция уходит в фоновый
   лоток, интерфейс не заперт, по завершении приходит уведомление.
6. Перейдите в пространство в левой рейке — **та же грамматика на уровне 2**: список
   чатов-задач, вкладки контекста, очередь карточек этого пространства.

Проверьте на прочность: кнопка **«Остановить»** во время стриминга, запрос про
**«выписку из ЕГРЮЛ»** (честная ошибка внешнего сервиса с «Повторить»), слово
**«расторжение»** (уточняющий вопрос агента), переключатель темы внизу рейки.

## Архитектурные решения

Подробности — в `docs/`. Коротко о главном:

**Платформа, а не экран.** Ядро (`src/core`) не знает о конкретных пространствах.
Новое рабочее пространство = один манифест (`WorkspaceManifest`) + сид-данные, без правок
в ядре и без изменения раскладки. В прототипе два разнотипных пространства —
«Обязательства по договорам» и «Судебные дела» — с разными типами карточек, вкладок
контекста и навыков агента, но одной оболочкой. Это доказательство переиспользуемости.

**Транспорт агента подменяем.** UI работает с интерфейсом `AgentTransport`, отдающим
поток событий (`token`/`status`/`citation`/`card`/`handoff`/`error`/…). Мок реализует
этот интерфейс; замена на реальный SSE-транспорт — одна строка в провайдере, компоненты
не меняются.

**Одна карточка — один рендерер.** Карточка действия в очереди «Сегодня» и в своём
пространстве — одна запись стора, отрисованная одним `CardRenderer`. Решение по карточке
в одном месте немедленно видно в другом.

**Честная латентность.** Три класса ожидания: <300 мс — без индикатора; 0.3–3 с —
статус в потоке чата; >3 с — операция уезжает в фоновый лоток, юрист свободен.
Бесконечного спиннера без подписи в интерфейсе нет.

**Кликабельные источники.** Каждое утверждение агента несёт ссылку на конкретный пункт
документа. Ссылка открывает документ в нужном месте и шарится через URL
(`?doc=..&anchor=..`). Целостность ссылок проверяется dev-ассертами при загрузке —
битая ссылка падает громко, а не молча.

## Стек

Vite · React 18 · TypeScript (strict) · React Router (HashRouter) · Zustand ·
CSS Modules · Radix UI (headless-примитивы) · lucide-react · date-fns.

Дизайн-система — собственная, на семантических CSS-переменных (`src/shared/styles/tokens.css`),
светлая и тёмная темы. UI-примитивы построены на headless-примитивах Radix (готовая
доступность) со своей стилизацией — без UI-китов, чтобы сохранить полный контроль над
плотностью и поведением. Адаптив двухуровневый: медиа-запросы решают судьбу колонок,
контейнерные запросы (`@container`) — внутреннюю раскладку компонентов, потому что ширины
панелей задаёт пользователь ресайзом.

## Структура

```
src/
  app/          роутер, провайдеры, тема
  shared/       ui/ (примитивы) · lib/ (утилиты, даты) · styles/ (токены, reset)
  core/         layout · chat · cards · calendar · documents · tasks · agent
  workspaces/   registry + obligations/ + litigation/ (манифесты пространств)
  store/        Zustand-слайсы, селекторы, dev-ассерты целостности
  pages/        TodayPage · WorkspacePage · SettingsPage
  types/        доменная модель
docs/           SPEC · DOMAIN · SCENARIOS · UX — контракты проекта
```

## Деплой

Настроен GitHub Actions (`.github/workflows/deploy.yml`): push в `main` собирает и
публикует на GitHub Pages. Включить один раз: Settings → Pages → Source → «GitHub Actions».

Сборка использует относительные пути (`base: './'`) и hash-роутинг, поэтому работает
на любом хостинге и в подпапке без правки конфигурации.
