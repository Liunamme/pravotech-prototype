## 1. Что это за проект

Прототип «ПравоТех» — B2B-платформа, где AI-агент выполняет работу юриста; юрист
подтверждает / изменяет / отклоняет предложения агента. React + TypeScript, Vite,
CSS Modules, Radix UI, Zustand. Агент замокан (сценарии в `src/core/agent`).

Базовый прототип (этапы 1–9) и редизайн десктопа по макету — **готовы**.
Подробности — `DEVLOG.md`, `docs/SPEC.md`, `docs/DOMAIN.md`, `docs/SCENARIOS.md`,
`docs/UX.md`, `docs/APP-STRUCTURE.md`. Макет — `design/design_handoff_pravotex_ui/`.

## 4. ⭐ Стиль работы заказчика (соблюдать строго)

- **По ОДНОЙ задаче за раз.** Даёт баг → фиксишь → проверяет → следующий.
- **НЕ коммитить без явного «коммить».** Сделал → показал скриншот/замер → ждёшь.
- **Под каждый баг — отдельная ветка** `fix/<что>`.
- **Проверять визуально и замерами.** Chrome-расширение в этой среде не работает;
  используется Playwright напрямую: скрипты `.mjs` в
  `<scratchpad>/pw/`, запуск `cd <scratchpad>/pw && node <script>.mjs`, порт 5199.
  Скриншоты читать через Read, важные — отдавать заказчику.
- Заказчик ценит **числа**: замеры отступов, computed-цвета, покадровые замеры
  анимации. Если баг не воспроизводится — честно сказать это и показать, что
  именно мерил.
- Отвечать по-русски, по делу.

## 5. ⭐⭐ Технические уроки (грабли, на которые уже наступали)

1. **`backdrop-filter` ломает прокрутку.** Элемент с фильтром становится
   «backdrop root», композитор Chromium перестаёт считать его целью колеса и
   отдаёт событие тому, что ПОД ним. Лечение: фильтр в отдельный инертный слой
   (`pointer-events: none`), содержимое — выше него без фильтра. Сделано в
   `DocumentInspector` (`.glass`). Если где-то ещё «проваливается» ввод — та же
   болезнь.
2. **`mask-image` на предке отключает `backdrop-filter` внутри.** Предок с
   маской — тоже backdrop root, и размытие внутри перестаёт работать. Из-за
   этого в очереди края отделаны вуалями, а не маской (`CardQueue`).
3. **Родной `scrollIntoView` тащит всю раскладку.** Он подкручивает КАЖДОГО
   предка, включая `overflow: hidden` и страницу. Использовать только
   `shared/lib/scrollIntoViewWithin.ts` (двигает единственный контейнер).
4. **`Tooltip.Trigger asChild` + `NavLink className={fn}`** — Radix склеивает
   className строкой, функция попадает в атрибут исходным текстом, стили не
   применяются. Активное состояние ссылок брать из `[aria-current='page']`.
5. **Акцентный цвет на акцентной подложке сливается.** На фиолетовом фоне текст
   берёт `--pt-text` (белый в тёмной, тёмный в светлой). Тот же принцип у
   активной иконки рейки.
6. **Скрим модалки не должен брать `--color-text`** — в тёмной теме он почти
   белый. Есть отдельный токен `--pt-scrim`.
7. **Родные контролы** (иконка `input[type=date]`, календарь, выпадашки) красит
   только `color-scheme` — он задан в `tokens.css` для обеих тем.
8. **Никаких literal-цветов вне `tokens.css`**: проверка
   `grep -rnE '#[0-9a-fA-F]{3,6}' src --include='*.module.css'`.
9. Полосу под логотип резервирует токен `--logo-safe-top` (рейка, настройки,
   витрина) — иначе логотип ложится на заголовок.

## 6. Эталонные решения (переиспользовать)

- **Динамическое затухание краёв прокрутки** — `shared/lib/useScrollFade.ts`:
  `--fade-top/-bottom` включаются, только когда за краем есть скрытый контент.
  Применено в списке договоров/дел.
- **Размытые вуали у краёв ленты** — `CardQueue`: sticky-полосы сверху/снизу с
  `backdrop-filter` и маской, включаются динамически. Sticky-заголовки групп
  фона не имеют.
- **Единая подсказка** — `shared/ui/Tooltip` (стекло оверлея). Своих копий
  заводить нельзя, рейка ходит через неё же.
- **Ссылки на документы** везде открывают инспектор и пишут `?doc=&anchor=`:
  чипы, строки сроков, предмет карточки.
