# SCENARIOS — поведение мок-агента и канон демо-данных

Контракт между этапом 4 (транспорт и сценарии) и этапом 8 (демо-данные).
Идентификаторы ниже — **каноничные**. Оба этапа обязаны использовать ровно их, иначе ссылки на источники разъедутся.

---

## 1. Модель времени

Прототип должен ощущаться живым, но не тратить время демонстратора.

| Параметр | Значение |
|---|---|
| Задержка между токенами | 16–34 ms со случайным джиттером |
| Пауза на знаке препинания | +60 ms после `.`, `:`, `;` |
| Задержка перед первым токеном («агент думает») | 500–900 ms |
| Шаг статуса длинной операции | 700–1400 ms |
| Порог ухода в фон | операция > 3 s |
| Появление карточки после текста | 350 ms |

Реализовать как `TIMING`-константу в `core/agent/timing.ts`, чтобы можно было ускорить всё разом (пригодится для отладки и для записи демо).

**Обязательно:** поток должен быть отменяемым. `AgentTransport.cancel(threadId)` прерывает генератор, `Composer` показывает кнопку «Остановить» во время стриминга.

## 3. Сценарии

Мок подбирает сценарий по ключевым словам ввода; если совпадений нет — работает `fallback`.
Файлы: `core/agent/scenarios/<name>.ts`, реестр в `core/agent/scenarios/index.ts`.

### 3.1 `morningDigest` — утренний дайджест (уровень 1)

**Триггер:** автоматически при первом открытии `/today` в сессии, а также по слову «дайджест».

**Поток:**
1. `status` «Собираю картину дня» (900 ms)
2. `status` «Проверяю сроки по 2 пространствам», `progress {1,2}` → `{2,2}`
3. `token`-поток:
   > Доброе утро. К этому часу требуют внимания четыре вещи.
   >
   > **Срочно сегодня.** По договору аренды №44-АР срок направления отказа от автопролонгации истекает завтра, 25 июля [источник: `a-lease-44-notice`]. Если не уведомить, договор продлевается ещё на 11 месяцев на прежних условиях [источник: `a-lease-44-renewal`].
   >
   > **Заседание 5 августа** по делу А40-118742. Ответчик 19 июля подал отзыв с двумя доводами, ключевой — пропуск срока исковой давности [источник: `a-a40-response-arg1`]. Позицию по нему я подготовил, нужна ваша проверка.
   >
   > **«Вектор» просит повысить цену** на 12% с 1 сентября [источник: `a-letter-vektor-claim`]. По договору поставки одностороннее изменение цены не предусмотрено — основания отказать есть [источник: `a-supply-118-delivery`].
   >
   > **Ещё две автопролонгации** — по договорам №27-У и №203/П — сработают в сентябре. Время есть, но решение лучше принять до конца месяца.
4. `card` ×4 (см. §4), с паузой 350 ms между ними
5. `done`

**Важно:** каждое содержательное утверждение несёт `citation`. Абзац без источника в этом сценарии — ошибка.

### 3.2 `autoRenewalScan` — сканирование портфеля (демонстрация прогресса)

**Триггер:** «автопролонга», «продлятся», «пролонгация», «портфел».

**Поток:**
1. `status` «Отбираю договоры с условием об автопролонгации» (1200 ms)
2. `status` «Читаю договоры», `progress` от `{0,12}` до `{12,12}` шагами по 1 каждые ~700 ms — **это ключевой момент демо честной латентности**, полоса должна двигаться заметно
3. `status` «Сверяю сроки уведомления с календарём» (900 ms)
4. `token`-поток с итогом + `block` типа `table`:

   | Договор | Контрагент | Пролонгация | Уведомить до |
   |---|---|---|---|
   | №44-АР | ООО «Прайм Ритейл» | 12.09.2026 | **25.07.2026** |
   | №27-У | ИП Соколов А. В. | 15.09.2026 | 16.08.2026 |
   | №203/П | АО «СЛА» | 20.09.2026 | 21.08.2026 |

   Таблица несёт `citations` на `a-lease-44-renewal`, `a-services-27-renewal`, `a-supply-203-renewal`.
5. `card` ×3 типа `renewal_notice` (P1, P2, P2)
6. `done`

### 3.3 `caseposition` — длинная операция с уходом в фон

**Триггер:** «позици», «подготов», «отзыв», «возраж».

**Поток:**
1. `status` «Изучаю материалы дела» (1000 ms)
2. `status` «Читаю отзыв ответчика», `progress {1,3}`
3. `status` «Подбираю практику», `progress {2,3}` (1400 ms)
4. **`handoff`** — операция объявляется долгой и уезжает в `BackgroundTaskTray`:
   ```
   task: {
     title: 'Подготовка позиции по делу А40-118742',
     steps: [
       'Анализ доводов отзыва',
       'Подбор практики ВС РФ',
       'Проверка срока исковой давности',
       'Сборка проекта возражений',
     ],
   }
   ```
   В чат при этом падает честное сообщение: «Это займёт около минуты. Я продолжу в фоне — можете заниматься другим, я сообщу.»
5. Задача идёт ~18 s, шаги переключаются, по завершении — тост «Позиция готова» со ссылкой на тред.
6. При возврате в тред — итоговое сообщение с `citations` на `a-a40-response-arg1`, `a-practice-14`, `a-a40-expert-conclusion` и `card` типа `hearing_prep` (P0).

**Это самый важный сценарий для тезиса ТЗ о латентности.** Он должен работать безупречно: уход в фон, свободная навигация, возврат к результату.

### 3.4 `priceIncreaseRefusal` — работа с письмом контрагента

**Триггер:** «вектор», «цен», «повышени», «отказ».

Короткий сценарий (~4 s): анализ письма → вывод, что одностороннее изменение цены договором не предусмотрено → `card` типа `obligation_breach` (P1) с проектом ответа.

### 3.5 `clarify` — уточняющий вопрос

**Триггер:** «расторг», «прекрат» (намеренно неоднозначные).

1. `status` «Уточняю условие» (700 ms)
2. `token`: «Уточните, о каком договоре речь — под условие подходят три.»
3. `clarify` с опциями: `['Аренда №44-АР', 'Поставка №118/П', 'Услуги №27-У']`
4. `done` — тред переходит в `awaiting_user`

Выбор опции отправляет её как реплику пользователя и запускает соответствующий сценарий.

### 3.6 `failure` — честная ошибка

**Триггер:** «росреестр», «егрюл», «выписк» (внешний источник — правдоподобная причина сбоя).

1. `status` «Запрашиваю сведения из ЕГРЮЛ» (1500 ms)
2. `error`: `{ message: 'Сервис ЕГРЮЛ не отвечает. Данные не получены — вывод делать не на чем.', retryable: true }`

Сообщение падает в `status: 'error'`, показывается кнопка «Повторить». Повтор проходит успешно и выдаёт короткий ответ.

**Формулировка ошибки — не «Что-то пошло не так».** Названа причина и сказано, что именно не удалось. Это часть продуктовой позиции: агент честен о своих пределах.

### 3.7 `fallback`

Короткий осмысленный ответ с одной ссылкой на подходящий по контексту документ + предложение навыков пространства (`skills`). Никогда не должен выглядеть как заглушка.

## 5. Требования к реализации

1. Сценарий — **асинхронный генератор**, а не таймауты с колбэками. Так он естественно отменяется.
2. Никаких `setTimeout`-цепочек в компонентах. Вся временна́я логика — внутри мока.
3. Мок не знает про React. Он чистый: вход — строка и контекст, выход — `AsyncIterable<AgentEvent>`.
4. Токенизация текста — по словам с сохранением пробелов, не по символам (по символам выглядит неестественно медленно).
5. `citation` приходит **после** соответствующего фрагмента текста и привязывается к последнему `text`-блоку.
6. Все тексты сценариев вынести в отдельные файлы данных, не смешивая с логикой потока.
